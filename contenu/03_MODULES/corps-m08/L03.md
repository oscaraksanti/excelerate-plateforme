## Le problème

Nadège ne demande jamais « quel est le chiffre d'affaires ». Elle demande **« par rapport à l'an dernier »**.

En formules, comparer une année à la précédente coûte une colonne, une table de correspondance, et une prière pour que les mois soient alignés. En DAX, c'est **une ligne** — à condition que la table de calendrier soit marquée.

Et une fois les mesures écrites, il reste à les sortir du tableau croisé, dont la forme change à chaque fois qu'une agence apparaît.

## Ce qu'on construit

Les comparaisons dans le temps, puis la restitution libre — et la porte vers Power BI.

## La time intelligence

Toutes ces fonctions ont un point commun : **elles prennent une colonne de dates en argument**, et elles ne fonctionnent que si la table est marquée comme table de dates.

### Comparer à l'an dernier

```
CA USD N-1 := CALCULATE ( [CA USD] ; SAMEPERIODLASTYEAR ( d_Calendrier[Date] ) )
```

*Calcule `CA USD`, mais sur la même période décalée d'un an.*

Et l'évolution, qui en découle :

```
Évolution % := DIVIDE ( [CA USD] - [CA USD N-1] ; [CA USD N-1] )
```

**La même mesure fonctionne à tous les niveaux** : par mois, par trimestre, par année, par agence. C'est ce qui rend le DAX rentable — en formules, il aurait fallu une colonne par niveau.

`DATEADD` fait la même chose en plus général :

```
CA USD M-1 := CALCULATE ( [CA USD] ; DATEADD ( d_Calendrier[Date] ; -1 ; MONTH ) )
```

### Les cumuls

```
CA USD Cumul Annuel := TOTALYTD ( [CA USD] ; d_Calendrier[Date] )
```

*Le cumul depuis le 1er janvier jusqu'à la fin de la période affichée.*

Sur le modèle du jour, à fin juin 2026 : **14 180 213,65 USD**.

`TOTALQTD` et `TOTALMTD` font le trimestre et le mois. Et pour un exercice qui ne commence pas en janvier — le cas de Baobab, dont l'exercice court d'octobre à septembre :

```
Cumul Exercice := TOTALYTD ( [CA USD] ; d_Calendrier[Date] ; "30/09" )
```

Le troisième argument est la date de clôture. **C'est le paramètre que personne ne connaît, et il évite de fabriquer une colonne d'exercice à la main.**

### Le cumul annuel mobile — les douze derniers mois

C'est la mesure que les directions préfèrent, parce qu'elle lisse la saisonnalité :

```
CA 12 mois glissants :=
CALCULATE (
    [CA USD] ;
    DATESINPERIOD ( d_Calendrier[Date] ; MAX ( d_Calendrier[Date] ) ; -12 ; MONTH )
)
```

*Le chiffre d'affaires des douze mois qui se terminent à la date affichée.*

> 🔴 **Si l'une de ces mesures rend vide, ne touchez pas à la mesure.** Vérifiez d'abord, dans cet ordre : ① la table de dates est-elle **marquée** ? ② couvre-t-elle **l'année entière**, y compris après la dernière vente ? ③ y a-t-il un **trou** dans les dates ? Dans quatre-vingt-dix pour cent des cas, c'est ①.

## La conversion multi-devises, en une seule table de taux

C'est la partie du modèle dont on est le plus fier, et elle tient en une mesure :

```
CA USD :=
SUMX (
    f_Ventes ;
    DIVIDE (
        f_Ventes[Montant_Local] ;
        SWITCH ( RELATED ( d_Agence[Devise] ) ;
                 "CDF" ; RELATED ( d_Taux[CDF] ) ;
                 "XOF" ; RELATED ( d_Taux[XOF] ) ;
                 "XAF" ; RELATED ( d_Taux[XAF] ) )
    )
)
```

Ce qu'elle fait, ligne par ligne : elle regarde **la devise de l'agence** de la ligne, va chercher **le taux du mois** de la ligne, et divise.

**Le taux appliqué est celui du mois de la vente, pas un taux moyen.** C'est la différence avec le module 7, où l'écart de 1,12 dollar venait précisément de là.

> **Pourquoi `RELATED ( d_Taux[CDF] )` fonctionne depuis `f_Ventes`.** La relation va de `f_Ventes` vers `d_Calendrier`, puis de `d_Calendrier` vers `d_Taux`. `RELATED` suit la chaîne, tant que chaque étape est plusieurs-à-un. C'est exactement ce qu'est un flocon — et c'est ici qu'il sert.

**La même mesure en devise locale** ne demande rien de plus : `CA Local := SUM(f_Ventes[Montant_Local])`. Une table de taux, deux mesures, et le rapport existe dans les deux unités.

## Les KPI de Power Pivot

Un objet qu'on n'utilise presque jamais et qui rend un vrai service : dans la fenêtre Power Pivot, clic droit sur une mesure > **Créer un indicateur de performance clé**.

On définit **une valeur cible** — une autre mesure, ou une valeur absolue — et **trois seuils**. Le TCD affiche alors une icône à côté du chiffre.

C'est le jeu d'icônes du module 6, mais **défini dans le modèle** : il suit la mesure partout, sur tous les tableaux croisés, sans qu'on refasse la mise en forme conditionnelle à chaque fois.

## 💎 `CUBEVALEUR` — sortir du carcan du tableau croisé

![Sortir du carcan du tableau croisé](/lecons/m08/08-cubevaleur.svg)

Un tableau croisé a une forme, et cette forme dépend de ses données : une agence apparaît, tout se décale. Le module 6 disait déjà pourquoi c'est un problème pour un tableau de bord.

`CUBEVALEUR` lit le modèle **depuis une cellule ordinaire** :

```
=CUBEVALEUR("ThisWorkbookDataModel";
            "[Measures].[CA USD]";
            "[d_Calendrier].[Annee].&[2026]";
            "[d_Agence].[Agence].&[Kinshasa]")
```

Trois choses à savoir :

1. **Le premier argument est le nom de la connexion.** Pour le modèle interne au classeur, c'est toujours `ThisWorkbookDataModel`.
2. **Le deuxième est la mesure**, entre `[Measures].[ ]`.
3. **Les suivants sont les filtres**, autant qu'on veut. `&[…]` désigne une valeur précise.

> 💎 **Et on ne les écrit pas à la main.** On fabrique le tableau croisé d'abord, puis : **`Analyse du TCD > Outils OLAP > Convertir en formules`**. Excel remplace chaque cellule par son `CUBEVALEUR`. Il n'y a plus qu'à déplacer les cellules où l'on veut.

C'est le tableau de bord du module 6 — grille imposée, tuiles d'indicateurs, formes liées — **alimenté par un modèle d'un million de lignes.** Les deux modules se rejoignent exactement ici.

*Les autres fonctions de cube : `MEMBRECUBE` désigne un membre, `JEUCUBE` un ensemble, `RANGMEMBRECUBE` le n-ième d'un classement. On en a rarement besoin.*

## Le pont vers Power BI

![Trois outils, trois moments](/lecons/m08/07-qui-fait-quoi.svg)

La question arrive toujours : *« et Power BI, alors ? »*

**Ce qui se transporte tel quel :**

- **Le modèle entier.** Power BI Desktop ouvre un classeur Excel contenant un modèle et le reprend : tables, relations, mesures DAX, colonnes calculées.
- **Les requêtes Power Query.** Le langage M est exactement le même.
- **La façon de penser.** Étoile, granularité, contexte de filtre, mesure contre colonne : rien ne change.

**Ce qui ne se transporte pas :**

- **Les feuilles Excel**, les formules, la mise en forme conditionnelle, les graphiques Excel.
- **`CUBEVALEUR`** — il n'y a pas de cellules dans Power BI.
- **Une partie du DAX récent**, dans l'autre sens : Power BI en a plus que Power Pivot. *(C'est l'objet de la leçon suivante.)*

> **Ce qu'il faut en retenir : le travail de ce module n'est jamais perdu.** Si votre entreprise passe à Power BI dans deux ans, vous ouvrirez votre classeur dedans et vous continuerez.

## Les pépites 💎

**1. `CUBEVALEUR`** libère du carcan du tableau croisé : un tableau de bord entièrement libre, alimenté par le modèle. Et on l'obtient par `Outils OLAP > Convertir en formules`, sans écrire une formule.

**2. La même mesure en devise locale et en USD**, par une seule table de taux et un `SWITCH` de trois lignes.

**3. Le modèle Excel s'importe directement dans Power BI Desktop.** Le travail n'est jamais perdu.

## Les erreurs fréquentes

- **Chercher l'erreur dans la mesure quand la time intelligence rend vide.** C'est la table de dates, neuf fois sur dix.
- **Une table de calendrier qui s'arrête à la dernière vente.** Les cumuls de fin d'année sont faux.
- **Oublier le troisième argument de `TOTALYTD`** quand l'exercice ne commence pas en janvier.
- **Écrire les `CUBEVALEUR` à la main.** `Convertir en formules` les écrit pour vous, sans faute de frappe.
- **Convertir un TCD en formules trop tôt.** L'opération est irréversible : le TCD disparaît. On le duplique d'abord.
- **Croire qu'un taux moyen suffit.** Le taux se prend au mois de la ligne. C'est tout l'intérêt d'avoir la date dans le modèle.

## Le mini-défi — 20 minutes

1. Écrivez `CA USD N-1` et `CA USD Cumul Annuel`.
2. Faites un TCD : les mois en lignes, `CA USD` et `CA USD N-1` en valeurs, l'année en filtre.
3. **Retirez la marque « table de dates »** et regardez ce qui se passe. Remettez-la.
4. Ajoutez `Évolution %`. Vérifiez qu'elle est juste au mois **et** au total.
5. Dupliquez le TCD, puis **convertissez la copie en formules**. Déplacez trois cellules ailleurs sur la feuille.

**À retrouver, année 2026 :** `CA USD` **30 317 122,55** · `CA USD N-1` **27 852 544,37** · évolution **+8,85 %** · cumul à fin juin **14 180 213,65**.

Le point 3 est l'exercice le plus utile du module : **voir de ses yeux une mesure devenir vide sans erreur** vaut trois explications.

## 🎯 Ton fichier à toi

La comparaison à l'an dernier est ce que votre direction demande le plus souvent, et c'est ce qui coûte le plus cher à produire à la main.

```
Voici le schéma de mon modèle, et mes mesures
actuelles :
[les tables, les relations, les mesures déjà écrites]

Ma table de calendrier couvre : [période]
Mon exercice comptable commence le : [date]

1. Écris-moi les mesures de comparaison dont j'ai
   besoin : même période l'an dernier, cumul depuis
   le début de l'exercice, douze mois glissants.
   Pour Power Pivot dans Excel 2024, pas Power BI.
2. Pour chacune, dis-moi ce qu'elle rend le mois
   où il n'y a pas d'équivalent l'an dernier.
3. Dis-moi ce qui casse si ma table de dates
   s'arrête à ma dernière vente.
4. Donne-moi trois cas de test avec la valeur
   attendue pour chacun, que je puisse vérifier.
```

Le point 2 attrape le piège classique : **le premier mois d'historique n'a pas de N-1**, et une évolution calculée sur zéro doit rendre vide, pas l'infini.

> **Apportez au direct votre comparaison N / N-1.** C'est la mesure qui fait le plus d'effet à montrer, parce que tout le monde sait combien elle coûte à produire autrement.

## Chez vous, demain

Regardez le rapport de votre service qui compare à l'an dernier. Cherchez comment la colonne N-1 est produite.

Si c'est un `RECHERCHEV` sur un fichier de l'année précédente, vous venez de trouver ce qui casse chaque mois de janvier.

## Le problème

Le prix d'un produit dépend de trois choses : le produit, l'agence, et le mois. Le tarif arrive sous forme de grille — les produits en lignes, les agences en colonnes, un onglet par trimestre.

Thomas cherche le prix de l'huile à Dakar en mars. Il compte les colonnes avec le doigt sur l'écran.

## Ce qu'on construit

Une recherche qui croise deux dimensions sans compter une seule colonne. Puis une clé composite pour les cas où la clé n'existe dans aucune colonne.

## Le concept

![Croiser une ligne et une colonne](/lecons/m04/02-recherchex-2d.svg)

Le troisième argument de `RECHERCHEX` — *quoi renvoyer* — n'est pas obligé d'être une colonne écrite en dur. **Ça peut être le résultat d'une autre recherche.**

Le `RECHERCHEX` intérieur choisit **la colonne**. Le `RECHERCHEX` extérieur choisit **la ligne**. Deux recherches, une formule, aucun numéro.

## Le pas à pas

### 1 — La recherche à deux dimensions

```
=RECHERCHEX(produit ;
            t_Tarifs[Produit] ; RECHERCHEX(agence ;
            t_Entetes ; t_Tarifs))
```

Lis-la de l'intérieur vers l'extérieur :

1. `RECHERCHEX(agence ; t_Entetes ; t_Tarifs)` trouve **la colonne** de l'agence dans la grille
2. `RECHERCHEX(produit ; t_Tarifs[Produit] ; ⟨cette colonne⟩)` trouve **la ligne** du produit dedans

> L'équivalent en 2016/2019 : `=INDEX(tableau ; EQUIV(produit ; produits ; 0) ; EQUIV(agence ; entêtes ; 0))`. Trois arguments, le même résultat, et ça marche partout.

### 2 — Quand la clé n'est dans aucune colonne

Parfois l'unicité ne tient pas à une seule colonne. Un prix est unique par **produit + canal + mois**. Aucune de ces colonnes n'est une clé ; les trois ensemble en sont une.

![La clé composite et son piège](/lecons/m04/05-cle-composite.svg)

```
=[@Produit] & "|" & [@Canal] & "|" & TEXTE([@Mois];"aaaa-mm")
```

On fabrique la clé dans une colonne, des deux côtés, puis on cherche dessus.

> 🔴 **Le séparateur doit être un caractère impossible dans les données.**
> `"ABC-1"` + `"2"` et `"ABC"` + `"1-2"` donnent tous les deux `ABC-1-2`. Deux lignes différentes, une seule clé — et un rapprochement faux que rien ne signale.
> Prends `|`, `¤` ou `~`. **Jamais `-`, jamais `/`, jamais l'espace** : ils existent déjà chez vous.

Et **la date se formate avant d'être concaténée**. `[@Mois]` collé tel quel donne `45717`, le numéro de série. `TEXTE([@Mois];"aaaa-mm")` donne `2026-03`. Les deux côtés doivent utiliser exactement le même format.

### 3 — La recherche sans clé composite : la multiplication booléenne

Il y a une autre voie, souvenir du module 2 :

```
=RECHERCHEX(1 ;
            (t[Produit]=produit) * (t[Canal]=canal)
            * (t[Mois]=mois) ; t[Prix] ; "absent")
```

On cherche la valeur `1` dans un tableau de VRAI/FAUX multipliés. Une seule ligne vaut 1 : celle qui remplit les trois conditions.

**Aucune colonne à ajouter, aucune clé à fabriquer.** C'est plus lent sur de très gros volumes, et c'est souvent plus lisible.

> ⚠️ Attention : `t[Mois]=mois` compare des dates. Si l'une des deux est du texte, le test est FAUX sans erreur. On a vu ça au module 3.

## Les cas difficiles

### Le quatrième argument, encore

```
=RECHERCHEX(x ; cle ; col ; RECHERCHEX(x ; autre_cle ; autre_col ; "introuvable"))
```

`si_absent` n'est pas limité à du texte : **c'est un plan B complet.** Cherche dans la table principale, et si tu ne trouves pas, cherche dans la table de secours.

### Les jokers

```
=RECHERCHEX("*MASINA*" ; t[Client] ; t[Ref] ; "absent" ; 2)
```

Le cinquième argument à `2` active les jokers `*` et `?`. Utile pour retrouver un client dont on ne connaît qu'un morceau du nom — **et dangereux** : deux clients peuvent correspondre, et `RECHERCHEX` rend le premier sans prévenir.

### La recherche binaire — à connaître pour l'éviter

Le sixième argument accepte `2` et `-2` : recherche binaire, beaucoup plus rapide sur des centaines de milliers de lignes.

> 🔴 **Sur des données non triées, elle ne renvoie pas d'erreur. Elle renvoie une mauvaise valeur.** C'est le piège le plus coûteux de la fonction, parce que le résultat a l'air normal. Ne l'utilisez que si vous contrôlez le tri — et écrivez-le dans le `README`.

## Les pépites 💎

**1 — `RECHERCHEX` peut renvoyer une plage, pas seulement une valeur.**

```
=SOMME(RECHERCHEX(debut ; t[Mois] ; t[CA]) : RECHERCHEX(fin ; t[Mois] ; t[CA]))
```

Deux `RECHERCHEX` séparés par un `:` définissent une **plage entre deux bornes trouvées**. La somme entre deux dates, sans `SOMME.SI.ENS`.

**2 — Le troisième argument peut être plusieurs colonnes.**
`=RECHERCHEX(ref ; t[Ref] ; t[[Client]:[Montant]])` renvoie **quatre colonnes d'un coup**, qui se déversent horizontalement. Une seule formule au lieu de quatre.

**3 — Le séparateur impossible.** 💎
Déjà dit, et c'est la pépite du jour : **le jour où votre clé composite se trompe, rien ne vous le dira.** C'est le genre d'erreur qu'on découvre six mois plus tard, en rapprochant une banque.

**4 — `TEXTE` avant de concaténer une date.**
Toujours. Des deux côtés. Avec le même format.

## Les erreurs fréquentes

- **Compter les colonnes.** Si vous comptez, vous vous tromperez un jour.
- **Un séparateur qui existe dans les données.** `-`, `/`, l'espace, le point.
- **Concaténer une date sans la formater.** Un côté donne `45717`, l'autre `2026-03`.
- **Utiliser les jokers sans vérifier l'unicité.** `*MASINA*` peut trouver deux clients.
- **La recherche binaire sur données non triées.** Le résultat a l'air juste.

## Le mini-défi — 12 minutes

Reprends `M04_L01_DEPART.xlsx`.

1. Fabrique une clé composite `Agence | Devise` dans une colonne
2. Écris la formule qui retrouve une commande à partir de cette clé
3. **Puis change le séparateur pour un tiret** et cherche une combinaison qui casse

Le point 3 est l'exercice. Il n'y a pas de solution : il y a une démonstration.

## 🎯 Ton fichier à toi

Regarde tes fichiers et cherche **une grille** : produits en lignes, périodes ou sites en colonnes. Tout le monde en a une — les tarifs, les effectifs par mois, les objectifs par agence, les stocks par entrepôt.

Aujourd'hui, quelqu'un y cherche une valeur en comptant les colonnes. Remplace ça.

Et si ta clé n'est dans aucune colonne :

```
Dans mon fichier, une ligne est identifiée de façon
unique par la combinaison de plusieurs colonnes :
[nomme-les]

1. Propose-moi la formule de clé composite, avec un
   séparateur qui ne peut pas exister dans MES
   données — dis-moi pourquoi tu l'as choisi.
2. Dis-moi comment formater chaque partie pour que
   les deux côtés produisent exactement la même clé
   (dates, nombres, majuscules, espaces).
3. Donne-moi une formule de contrôle qui vérifie
   qu'aucune clé n'apparaît deux fois.
4. Donne-moi deux exemples de valeurs qui
   produiraient la MÊME clé par accident.
```

Le point 4 est le plus instructif. Demande-le systématiquement.

> **Apporte ta grille au direct.** Les recherches à deux dimensions sont la question la plus fréquente après « pourquoi mon RECHERCHEV ne trouve rien ».
